# CardiacArrhythmiaModulation (CAM)

> **Computational framework for studying cardiac arrhythmia modulation by fibrosis architecture** — integrating synthetic mesh generation, structural topology analysis, and electrophysiological simulation.

---

## Overview

This repository contains the complete computational pipeline associated with the study:

> *[Article title — to be updated upon publication]*
> Authors: [Author list]
> Journal: [Journal name] | DOI: [DOI — to be updated]

The **CAM framework** investigates how different fibrosis phenotypes modulate the vulnerability to sustained cardiac arrhythmias (re-entrant excitation). It is structured as a three-stage pipeline:

1. **Mesh generation** — Synthetic fibrotic tissue meshes are generated by the GNT (Geometry-Noise-Threshold) pipeline, implemented in GNU Octave (`perlin-fibrosis-generator/`), producing `.alg` files compatible with finite volume solvers.
2. **Structural characterization** — Each mesh is characterized by a suite of morphological, topological, and spatial metrics computed in Python (`scripts/fibro_metrics.py`), including Betti numbers (via GUDHI), fractal dimension, Moran's I, cluster geometry, and percolation-based conduction efficiency.
3. **Electrophysiological simulation** — Each mesh is submitted to [MonoAlg3D](https://github.com/rsachetto/MonoAlg3D_C), a GPU-accelerated finite volume solver for the cardiac monodomain equation, using the ten Tusscher–Noble–Noble–Panfilov (TNNP) cell model under ischaemic conditions (`[ATP]i` modulation). Sustained re-entry is detected from the simulation end-time.

The entire workflow is orchestrated by a single entry point (`scripts/orchestrator.py`), with downstream statistical analysis performed in Python and R.

## Fibrosis Phenotypes

Five phenotypes of cardiac fibrosis are modelled, based on the Perlin noise parameters from [Lawson et al. (2024)](https://doi.org/10.1016/j.media.2024.103240):

| Phenotype | Description |
|---|---|
| **Uniform** | Randomly distributed fibrosis with no spatial structure (baseline reference) |
| **Compact** | Dense, contiguous scar entirely devoid of myocardium |
| **Diffuse** | Short, scattered collagen segments dispersed throughout the tissue |
| **Interstitial** | Fine reticular mesh accumulating between cardiomyocyte clusters |
| **Patchy** | Long, irregular strands deeply interwoven with myocardial bundles |

## Dependencies

The pipeline depends on three separate environments. All must be set up before running.

### 1. MonoAlg3D (EP Solver)

MonoAlg3D requires a **Linux system** with an **Nvidia GPU** and **CUDA**.

```bash
# Navigate to the solver directory
cd MonoAlg3D_C

# Follow the setup guide for your OS:
# Ubuntu: guide-monoalg3d-ubuntu.md
# Fedora: guide-monoalg3d-fedora.md

# Compile
./build.sh
```

The binary will be placed at `MonoAlg3D_C/bin/MonoAlg3D`. See [MonoAlg3D_C/README.md](MonoAlg3D_C/README.md) for detailed instructions.

> **Citation for MonoAlg3D:**
> Oliveira RS et al. *Performance evaluation of GPU parallelization, space-time adaptive algorithms, and their combination for simulating cardiac electrophysiology.* Int J Numer Meth Biomed Engng. 2018;34:e2913. https://doi.org/10.1002/cnm.2913

### 2. Mesh Generator Environment (Octave + Python via Conda)

The GNT generator requires **GNU Octave 8.4** and a Python 3.12 environment.

```bash
# Create and activate the environment
conda env create -f perlin-fibrosis-generator/environment.yml
conda activate gnt-env

# Compile the Perlin noise MEX extensions (required once)
cd perlin-fibrosis-generator/helpers
mkoctfile --mex Octave2D.cpp
mkoctfile --mex Octave3D.cpp
cd ../..
```

### 3. Python Analysis Environment (Conda or pip)

The orchestrator and all analysis scripts use the CAM Python environment.

**Option A — Conda (recommended for full reproducibility):**
```bash
conda env create -f environment/cam_python_env.yml
conda activate cam-env
```

**Option B — pip:**
```bash
pip install -r requirements.txt
```

### 4. R Dependencies

The statistical modelling script (`scripts/statistical_models.R`) requires R ≥ 4.3 with the following packages, which are installed automatically on first run if absent:

- `mgcv` — Generalized Additive Models (GAM)
- `ggplot2` — Visualization
- `dplyr` — Data wrangling
- `brglm2` — Firth's bias-reduced logistic regression
- `scales` — Plot scales

## Quick Start

### Running the Full Pipeline

The full pipeline (mesh generation → structural metrics → EP simulation → analysis) is orchestrated by `scripts/orchestrator.py`.

```bash
# Activate the analysis environment
conda activate cam-env

# Run the orchestrator (example: 2D full scenario, all 5 phenotypes)
python scripts/orchestrator.py \
    --ftypes all \
    --base_config configs/base_config.ini \
    --batch_dir simulation_output \
    --dim_mode 2D \
    --shape full \
    --angles 0 30 60 90 \
    --min_den 0.10 \
    --max_den 0.90 \
    --dens_step 0.05 \
    --num_seeds 100 \
    --atpi_vals 2.0
```

Key arguments:

| Argument | Description | Default |
|---|---|---|
| `--ftypes` | Fibrosis phenotype(s): `compact`, `diffuse`, `interstitial`, `patchy`, `uniform`, or `all` | required |
| `--base_config` | Path to the base MonoAlg3D `.ini` configuration file | required |
| `--batch_dir` | Output directory for all results | timestamped |
| `--dim_mode` | Simulation dimensionality: `2D` or `3D` | `2D` |
| `--shape` | Fibrotic region geometry: `full`, `ellipse`, `box` | `full` |
| `--angles` | Fiber orientation angles (degrees) | `0 30 60 90` |
| `--min_den`, `--max_den`, `--dens_step` | Fibrosis density range and step | `0.1`, `0.9`, `0.05` |
| `--num_seeds` | Number of random realizations per condition | `100` |
| `--atpi_vals` | Intracellular ATP concentration(s) in mM | `2.0` |
| `--keep_meshes` | Retain `.alg` mesh files after simulation (disk-intensive) | `False` |

The orchestrator writes results incrementally to `<batch_dir>/<dim_mode>/<shape>/data/master_dataset.csv`, supporting interrupted/resumed runs.

### Running Only the Analysis Pipeline

If you have a pre-computed `master_dataset.csv` (e.g., from `chaos_paper_revision_batch/`), run the downstream analysis directly:

```bash
# Activate the analysis environment
conda activate cam-env

bash scripts/run_pipeline.sh chaos_paper_revision_batch 2D full
```

This executes the five analysis stages in order:
1. Dataset sorting (`organize_dataset.py`)
2. Structural analysis (`analyze_structure.py`)
3. Empirical/EP analysis (`analyze_empirical.py`)
4. R statistical models (`statistical_models.R`)
5. Multivariate analysis (`multivariate_analysis.py`)

Output figures and reports are saved to `<batch_dir>/2D/full/analysis/`.

### Generating a Single Mesh (Quick Test)

```bash
conda activate gnt-env
cd perlin-fibrosis-generator
octave-cli run_examples.m
```

This produces 4 example meshes (2D and 3D) in `perlin-fibrosis-generator/examples/`.

## Structural Metrics Computed

For each simulated mesh, the following metrics are extracted:

| Metric | Category | Description |
|---|---|---|
| `norm_mean_cluster_size` | Morphology | Mean fibrosis cluster size, normalized by grid area and weighted by cluster size |
| `mean_aspect_ratio` | Morphology | Area-weighted mean bounding-box aspect ratio of fibrosis clusters |
| `fractal_dimension` | Texture | Box-counting fractal dimension of the fibrosis pattern |
| `morans_i` | Texture | Spatial autocorrelation (Moran's I) with inverse-distance weighting (radius = 2 cells) |
| `betti_0` | Topology | Number of connected components of the conduction network (Betti-0) |
| `betti_1` | Topology | Number of independent loops in the conduction network (Betti-1) |
| `betti_2` | Topology | Number of encapsulated fibrosis in the conduction network (Betti-2) |
| `percolates_x` | Connectivity | Binary: whether a conduction path exists from left to right border |
| `min_path_x` | Connectivity | Length of the shortest conduction path (BFS, Von Neumann neighborhood) |
| `topological_conduction_eff` | Connectivity | Grid width divided by mean path length (tortuosity-based efficiency) |
